Parcel to Tax Agencies: Findings and Approach

Automating the identification of tax collecting agencies from a parcel address and parcel number. Based on the Operations sample file Parcels_With_Mulitple_Agencies.xlsx. Written 2026-11-16.

1. Summary

Recommendation: use a hybrid pipeline. Geocode the address to get the county, then let Claude (with web search) research the property, and have Claude choose from that county's list of known agencies instead of writing agency names freely. Add a small data-driven rule for county "delinquent" collectors.

Current result on a 50-parcel test: 56% recall (128 of 227 Operations agencies found) and 88% precision (128 of 145 returned were correct). The first, simplest version scored about 31% on both (3 parcels). The earlier 10-parcel test (58% and 86%) is consistent with the larger run.

Status: the 50-parcel baseline is done. Every parcel got at least one correct agency. The remaining gap is mostly agencies the system does not return (recall), not wrong ones (precision).

  • The sample shows ZIP code alone cannot identify the agencies, so a simple lookup table is not enough.
  • The agency numbers in the file encode the county, which makes it easy to restrict the candidate list once the county is known.
  • The best remaining gaps are special districts (MUD, WCID, management districts) and some collectors Operations adds that no public web page mentions.

Findings

  1. ZIP does not determine the agencies. Of 561 ZIP codes, only 384 map to a single set of agencies, and those cover just 574 of the 1,843 parcels (31%). School districts and special districts cut across ZIP boundaries.
  2. Agency numbers are structured. The first two digits are the state code and the next three the county code, so 131210000 is Fulton County, GA and 48201xxxx is anything in Harris County, TX. This is the same code the US Census uses, which is what makes geocoding useful here.
  3. Every parcel has a layered set of agencies: a county, a city or township, a school district, plus often special districts (MUD, WCID, solid waste, sewer, BID, management districts).
  4. Operations lists collectors, not every entity that levies a tax. A county that collects for its flood control, hospital and port districts appears once, as the county. The original prompt.txt asks for every entity that levies tax, which over-produces (see iteration 1).
  5. Some agencies exist only because of how Operations tracks delinquency: for example "Northampton County Tax Claim Bureau" or "Carbon County (Delinquent Only)", plus a law firm (Portnoff Law Associates, 133 rows). Only 58 of 212 counties have such an agency, and within those counties many parcels do not (see section 6).
  6. The names are Operations' own labels, for example Atlanta City (Fulton), HC MUD 163 (Harris) and entries marked INACTIVE. Any answer from outside has to be mapped to these.
  7. Data quirks: AgencyCount is unreliable for large parcels; state and city casing is mixed (Ny, ATLANTA); parcel numbers contain stray spaces; 1,151 rows have no tax_collector_property_number.
  8. The sample is not a random cross-section. The file is named "with multiple agencies" and covers a limited set of counties, so accuracy on other counties is unproven.

Chosen: a hybrid of B and C, plus a small rule. Option D is the long-term route for counties that matter most, but it does not suit a first, simple solution.

4. The solution as built

1. GeocodeUS Census geocoder returns county code, city, township and school district. No API key.
2. ResearchClaude with web search lists the taxing entities, given the geocoded facts as anchors.
3. PickClaude chooses from the county's agency list (from the Excel master) and returns agency numbers only.
4. RuleAdd the county's delinquent / tax claim collectors where the data supports it.
  • The county code from the geocoder selects the candidate list: every agency whose number starts with that code.
  • If the geocoder cannot find the address, the county that Claude names in step 2 is used instead.
  • Claude can only return numbers from the candidate list, so it cannot invent an agency.
  • The model runs on the Azure AI Foundry deployment configured in .env. The first prompt is the one from prompt.txt with two additions: ask for the county on the first line, and the geocoded facts.

What each step taught us

  • Iteration 1 failed for two reasons. The prompt returns every taxing entity (flood control, port, hospital), but Operations records only collectors. And fuzzy name matching both missed true matches ("Aldine Independent School District" vs Aldine ISD (Harris)) and accepted wrong ones ("Grimes Central Appraisal District", "Brazoria MUD 66").
  • Iteration 2 fixed both by giving Claude the county's list of Operations' own agencies to choose from, with an instruction about collectors. Recall rose from 31% to 51% and precision from 31% to 76%.
  • Iteration 3 added the delinquent rule. The Reading, PA parcel went from 0 to 2 correct because the Berks County delinquent collector was added.
  • Iteration 4 (geocoding) did not change the totals on this small sample, but it changed which answers are right. The Reading parcel now gets the correct borough (Laureldale Borough, Muhlenberg School District) as Census geography says, where before it returned Muhlenberg Township. The county no longer depends on Claude guessing it. Other gains are expected to show on a larger sample and are not yet proven.

6. Justification of each design decision

Start with Claude and web search rather than a lookup table

The ZIP analysis rules out a simple table. Scraping every county site is too large for a first version. Claude with search needs no per-county code and works anywhere, so it gives the fastest route to a measurable baseline.

Choose from a candidate list instead of writing names

Free-text names do not match Operations' labels, and fuzzy matching was the main cause of error in iteration 1. Choosing from a fixed list guarantees every answer is a real, trackable agency, and it applies the "collectors, not every taxing entity" distinction through the instruction. The cost is that an agency missing from the sample file can never be returned (see limitations).

Use the geocoder for the county

The Census county code equals the first 5 digits of the agency numbers, so it selects the candidates with no matching logic. In a 30-parcel check the geocoder found 21 addresses (70%), and for all 21 the county code was present in Operations' agency numbers. It is free, needs no key, and returns city, township and school district as extra facts for Claude. Addresses it misses use Claude's county as a fallback.

Delinquent rule with a threshold, not "always add"

Adding a county's delinquent collectors to every parcel in that county looks sensible, but the data says otherwise. We simulated it on all 1,843 parcels:

RuleCorrect entries addedWrong entries addedShare correct
Always add where a county has one24563628%
Only where at least 50% of that county's parcels have one (used)1344674%
Only where at least 75% have one811485%

Operations has 286 delinquent entries in total. "Always add" would drag precision far below the current 76-86%, so it was rejected. The 50% cut-off balances more recall against a precision close to the baseline. For example, only 22% of Northampton County parcels carry the Tax Claim Bureau, so it is not added there.

Caveat: the cut-off is learned from this same file, so the measured gain is optimistic. It needs a proper hold-out test (see plan).

Keep the code small

The brief asked for simple, traceable code. Each step is one short function, there are no retry layers or catch-all error handling, and every run prints the geocoded facts, the expected agencies and the chosen agencies side by side so any answer can be traced.

7. Known limitations and risks

  • Modest test size. The baseline is 50 parcels (about 3% of the 1,843), with only 1 Michigan parcel. Claude's answers also vary between runs (one parcel returned 3 agencies in one run and 1 in the next), so differences of one or two agencies are noise. The Michigan, New York and per-county figures are too thin to rely on.
  • Special districts are the weakest area. Claude returned HC MUD 162 as well as the correct HC MUD 163, and missed Clear Lake City Water Authority and HC WCID 156 on another parcel. The Census has no MUD or WCID boundaries.
  • The agency list comes from the sample file. An agency not in the file cannot be returned, and a county not in the file has no candidates. The file has 212 county codes, which is not nationwide.
  • Operations' data is not always a perfect reference. For 1507 Elgin Ave the Census places the address in Houston ISD while Operations lists Spring Branch ISD. Also, entries marked INACTIVE appear in the expected lists. Accuracy figures are measured against Operations' answers, not against reality.
  • Geocoder coverage is about 70% on this sample (rural routes, new streets, some FM roads). Misses use the weaker fallback.
  • Cross-county parcels. A Chappell Hill, TX parcel lists agencies from two counties (Washington and Austin CAD). The candidate list covers one county only.
  • Collectors Operations adds by internal practice (a law firm, "Delinquent Reporting Only" entries) cannot be found from public sources and rely on the rule.
  • Unverified: cost and time per parcel have not been measured, and the web search tool's behaviour on the Azure deployment is only tested on a few dozen calls.
  • Privacy: addresses are sent to the Census geocoder and to the model and its search tool. These are property addresses, but confirm this is acceptable under your data policy.

9. Questions for Operations

  1. Is the agency list in this file the complete, current master? If not, can we have the full list, including which entries are INACTIVE?
  2. When is a "Delinquent Only" or "Tax Claim Bureau" agency attached to a parcel? Is it tied to the parcel being delinquent, to the county, or to the client? Knowing this would replace the statistical rule.
  3. How should the Portnoff Law Associates entry be treated? It appears on 133 rows and cannot be found by research.
  4. Which accuracy would be good enough to use without a human check, and should missing an agency or adding a wrong one cost more?
  5. Which states and counties matter most for the first release?
