1. What the solution does

You give it a parcel address, a parcel ID (with state and county), or both. It answers three questions in order:

  1. Is the address real? (validate address)
  2. Which parcel is it, and is that parcel in the county's records? (find / validate parcel)
  3. Which agency collects the property tax on it? (find / validate agency)

Nothing is looked up from a stored list of agencies. Every answer is fetched at search time from a public source, and the result says how well it was checked.

3. Workflow

4. How the address is validated

Validation uses only the US Census Bureau. Nothing is stored locally.

  1. Match the address. The address is sent to the Census Geocoder (one at a time, or in one batch call when 10 or more are searched together). If Census cannot match it, the address is invalid and the reason is stated.
  2. Read the result. Census returns the standard form of the address, the state, the county, and a map point.
  3. Look up boundaries at that point in TIGERweb: the county, the incorporated city (none means unincorporated), and the school districts.
  4. Cross-check. If you also gave a state or county that disagrees with Census, the address is kept, Census wins, and a flag says so. If the geocoder and TIGERweb disagree on the county, that is flagged too.
What this does not prove. Census places an address by estimating a position along the street, so it can accept an address that has no parcel. That is why stage 2 checks the county's own records. Example: 4800 Ravenna Ave NE, Seattle passed here, yet King County has no such parcel.

For a parcel ID search there is no address to check, so stage 1 is skipped. Once the parcel is found, its own address is run through these same steps.

6. How the agency is found

Verified route (Maricopa AZ, King WA)

  1. A headless browser opens the county treasurer's property tax page for the parcel and shows the latest statement.
  2. The page text goes to Claude, which reads off the collecting agency, its payment address, the taxing bodies on the statement, and any separate collectors.
  3. The code checks that the parcel number appears on the page. Only then is the agency marked validated.
  4. The statement page is printed to a PDF and saved as the tax bill.

Web research route (all other counties)

  1. Claude searches the web for the county's property tax collector and reads the pages it finds, using the Census boundaries from stage 1 as fixed facts.
  2. It returns the agency, payment address, portal link, taxing bodies and a bill link if one exists. A bill link is downloaded if it works.
  3. The answer is marked found_unverified, because no county statement was read.

If a county's website script fails (for example the site changed), the pipeline falls back to web research and adds a flag saying so.

Example, 12515 West Windsor Boulevard, Litchfield Park, AZ 85340: Census matched the address and county (Maricopa), then the Assessor's map service returned parcel 508-12-628 at the same address, then the Treasurer's statement page showed that parcel and the agency Maricopa County Treasurer's Office. Status success, confidence 100.

8. What comes back

  • Status: success (parcel in county records and agency read from the statement), found_unverified (found by web research), parcel_not_found, parcel_ambiguous, county_needed, invalid_address, agency_not_found, exception_multi_agency and others.
  • Three sections mirroring the stages: the address check, the parcel (ID, address, source, verified or not, suggestions), and the agency (name, payment address, portal, validated, taxing bodies, separate collectors).
  • Confidence score (0-100) and the evidence behind it.
  • Cost of the search by stage: Claude calls, tokens, web searches and dollars.
  • Tax bill PDF when one was captured.

9. Limits to know about

  • Only two counties (Maricopa AZ, King WA) have the verified route. Every other county depends on web research, whose answers are not verified and vary between runs. Adding a county means writing one adapter file.
  • Some portals block automated browsers (county-taxes.com sites, for example San Francisco CA and Orange FL, use a challenge page). These are deliberately not bypassed, so those counties rely on web research.
  • Web research can be slow and costly when it cannot find an answer: one uncapped failed search measured $7.53. Each web research call is now capped at 6 searches and 4 page fetches (MAX_SEARCHES, MAX_FETCHES in portal.py); the Orlando example then took 52 seconds and $0.60.
  • Census can reject valid rural or new addresses; those return county_needed unless a state, county and parcel ID are supplied.
  • A ZIP code does not decide the agency (it can span counties and districts), so it is used only to narrow the street search.
