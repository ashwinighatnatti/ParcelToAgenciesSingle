single_collector: Developer Guide

A walk through the code for engineers who will extend it: the search pipeline (single_collector/), its web UI (django_ui/) and the three outside files they depend on. Written 2026-11-17 for the three-stage design. Functions are named rather than numbered by line, so this stays accurate as the files change. For what each feature does and how it was tested see Feature_Specification.html; for the data flow with worked examples see Search_Flow.html.

Things to know about the dependencies.

  • portal.py adds the project folder to sys.path and imports agent, which creates the Azure client and reads three environment variables at import time. Importing stages (and so run and the Django views) fails without a valid .env, even for a search that never calls Claude.
  • The Django settings change the working directory to the project folder, because the pipeline reads .env, the Excel file and downloads/ by relative path.
  • jurisdictions and rank_states are only for the ranking. The search path (run, stages) does not import them.

3. Runtime flow of one search

Entry point: run.process(query, geocoded=NOT_GEOCODED). query is a dict with any of address, parcel_id, state, county (empty strings are treated as missing).

#StepCodeOutcome / branch
0Normalise the query; find the search modeprocessNo address and no parcel id → status: error. Otherwise mode is address, parcel_id or both
0bBatch geocoding (CLI only)run.py main → census.geocode_batchWith 10 or more addresses all are geocoded in one request; each search then receives its result as geocoded
1Stage 1 validate the addressstages.validate_addressNo address → valid: None. No Census match → valid: False. Otherwise normalized address, county code, boundaries, flags
2Stage 2 find / validate the parcelstages.find_validate_parcelCounty known? adapter? by id / by address / web research → matched, ambiguous, not_found, county_needed, county_unknown, not_searched
2bValidate the parcel's own addressprocessParcel-only search that matched: run stage 1 on parcel["full_address"]
3Stage 3 find / validate the agencystages.find_validate_agencyMatched + adapter → statement page. Matched, no adapter → web research. Not matched → county-level research. Returns (agency, tax_bill)
4Choose the statusprocessSee section 9
5Assemble the recordprocessstatus, reason, query, address_validation, parcel, agency, tax_bill, flags

Stage 2 in detail (find_validate_parcel)

address valid?        ──yes──► county = Census county of the address
   │ no
parcel id + state + county? ──yes──► county = census.resolve_county(state, county)   (None -> county_unknown)
   │ no
parcel id only          -> county_needed            no parcel id, bad address -> not_searched

adapter = PORTALS.get(county_code)
  none            -> parcel_by_web_search()   Claude finds parcel + address + agency in one answer (verified=False)
  parcel id given -> parcel_by_id()           adapter.search_by_parcel; compare its address with the input if both given
  address only    -> parcel_by_address()      adapter.rows_on_street(core_word, zip) -> keep same street -> exact? one / several / none (nearest 5)

Stage 3 in detail (find_validate_agency)

parcel status in (county_needed, county_unknown, not_searched)      -> agency not_searched, no bill
parcel matched and adapter:
    agency_from_statement():  capture_statement (browser) -> portal.read_statement (Claude reads page text)
                              validated = parcel number found in the page text; portal host from the page URL; PDF saved
    on any exception          -> fall through to web research, with a flag
parcel matched, no adapter    -> web research from stage 2 (validated only if the source was "portal"); bill via bill.download_bill
parcel not matched            -> county-level web research (validated False, basis county_level_search), no bill

4. Data contracts

The package passes plain dicts. These are the shapes each function expects and returns; a mismatch shows up as a KeyError.

Query

{"address": "400 Broad St, Seattle, WA 98109" | None,     # "street, city, ST zip"
 "parcel_id": "1985200495" | None,
 "state": "WA" | None, "county": "King" | None}           # state and county are needed for a parcel-only search

address_check (stage 1)

{"checked": True, "valid": True,
 "normalized_address": "400 BROAD ST, SEATTLE, WA, 98109", "street": "400 BROAD ST", "city_name": "SEATTLE",
 "state": "WA", "zip": "98109", "county": "King County", "county_code": "53033",
 "coordinates": {"x": ..., "y": ...}, "city": ["Seattle city"], "school_districts": ["Seattle Public Schools"],
 "flags": [], "note": "..."}
{"checked": True, "valid": False, "flags": [], "reason": "The Census geocoder found no match for this address."}
{"checked": False, "valid": None, "flags": [], "reason": "Searching by parcel id: ..."}

The batch geocoder returns only matched_address, x, y and county_code. validate_address needs nothing else from the geocoder: county name, city and school districts come from TIGERweb and the state from the normalized address.

Parcel row (returned by adapters)

{"parcel_id": "1985200495", "parcel_address": "400 BROAD ST", "city": "SEATTLE", "zip": "98109"}

parcel (stage 2)

{"status": "matched" | "ambiguous" | "not_found" | "county_needed" | "county_unknown" | "not_searched",
 "county_code", "county", "state",                     # present once the county is known
 "parcel_id", "parcel_address", "full_address",        # matched only; full_address = "street, city, ST zip"
 "verified": bool,                                     # True only when found in the county's own records
 "source": "county_gis" | "claude_search",
 "address_matches_input": bool,                        # when an address was also given
 "candidates": [parcel row, ...],                      # ambiguous and not_found
 "reason": str | None, "flags": [str],
 "research": {...}}                                    # web-research route only; reused by stage 3, dropped from the output

agency and tax_bill (stage 3)

{"status": "found" | "not_found" | "not_searched", "validated": bool,

 "separate_collectors": [str], "levying_bodies": [str],
 "collector_model": "single" | "multiple" | "unknown",   # multiple: a separate collector named; single: 2+ taxing bodies on one statement
 "tax_year", "checks": [str], "notes": str}

{"available": True, "tax_year": "2026", "file_path": "downloads\\WA\\King_County\\1985200495_2026_bill.pdf"}
{"available": False, "reason": "..."}

5. Module reference: pipeline

stages.py the three stages

FunctionBehavior
clean, house_number, street_name, same_street, same_house, core_wordAddress string helpers. clean upper-cases and strips punctuation. same_street is true when two street names (number removed) are at least SIMILAR (0.85) alike by difflib, so AVE/AV match but NE RAVENNA BLVD does not match RAVENNA AVE NE. core_word is the longest word of the street name, used to query the county (RAVENNA).
validate_address(query, geocoded=NOT_GEOCODED)Stage 1. geocoded lets the batch geocoder's answer be passed in; None means "batch found no match" and is not retried. Reads the state from the normalized address, calls TIGERweb for county, city and school districts, and adds flags when the input state or county differs from the Census or when the geocoder and TIGERweb disagree.
parcel_matched, candidateBuild the matched result and a suggestion entry from a parcel row.
parcel_by_id(adapter, parcel_id, address_check, county, state)Looks the parcel up; not found gives a reason. When the address is valid too, compares the parcel's street with the address and sets address_matches_input and a flag.
parcel_by_address(adapter, address_check, county, state)Fetches rows on the street, keeps the same street, then: exactly one with the house number → matched; several → ambiguous; none → not_found with the NEAREST (5) nearest house numbers and a reason.
parcel_by_web_search(address_check, county, state, parcel_id)No adapter: portal.research_property. Matched but verified only if Claude says the parcel came from a county portal; otherwise a flag says it is third-party.
find_validate_parcel(query, address_check)Stage 2. Chooses the county (from the address, or census.resolve_county for a parcel-only search), then the route above.
agency_record(...)Builds the agency dict and derives collector_model.
agency_from_statement(adapter, parcel)capture_statement → portal.read_statement → checks the parcel number is in the page text (digits only) → portal host from the page URL → saves the PDF. Returns (agency, tax_bill).
find_validate_agency(query, address_check, parcel)Stage 3. See the diagram in section 3. Mutates parcel["flags"] when the adapter fails.

run.py

ItemBehavior
process(query, geocoded)Runs the three stages (with the extra stage 1 for a parcel-only match), chooses the status, assembles the record. See sections 3 and 9.
PARCEL_PROBLEMSMaps a stage 2 status to the result status (not_found → parcel_not_found, not_searched → invalid_address, and so on).
read_queries(args)From --file (CSV, utf-8-sig), from positional addresses (with optional --parcel --state --county), or from --parcel alone.
main blockargparse; batch geocoding at BATCH_MIN (10); loop with per-search error isolation; writes the manifest to --manifest (default output/manifest.json) and prints it.

census.py

FunctionBehavior
geocode_batch(addresses)One /addressbatch request for the addresses that parse as street, city, ST [zip]. An address that does not parse is reported as no match (it no longer stops the run). Returns {address: {matched_address, x, y, county_code} or None}.
tigerweb_boundaries(x, y)ArcGIS identify for school districts (layers 14, 16, 18), cities (26, 28) and counties (82). Raises IndexError if the point is in no county.
query_layer(layer_id, where, fields)Small helper to query a TIGERweb layer.
resolve_county(state, county)State abbreviation → state code (layer 80); county name (with or without "County"/"Parish"/"Borough") → county code (layer 82). None unless exactly one county matches. This replaces any fixed county table.

portal.py Claude's two jobs

ItemBehavior
first_json_object(text, defaults)Decodes the first JSON object in a reply (ignoring code fences and commentary). With no {, returns the defaults with the prose (first 400 characters) as notes. Keys Claude left out get their default, so callers never hit a KeyError.
research_property(address, county, state, parcel_id, boundaries)Web search and web fetch. address and parcel_id may each be None. Asks for parcel id and its source, parcel address, agency and address, taxing bodies, separate collectors, tax year and bill link. Never to guess a parcel id.
read_statement(captured, parcel_id)No tools. Gives Claude the statement page's text (first 12,000 characters), title and URL, and asks it to use only that text for the agency, its printed address, the taxing bodies, any separate collector and the parcel number shown.

bill.py

FunctionBehavior
save_pdf_bytes(content, state, county, parcel_id, tax_year)Writes downloads/{state}/{county}/{parcel}_{year}_bill.pdf with unsafe characters replaced; returns the path.
render_page_to_pdf(url)Headless Chromium prints an HTML page to PDF (networkidle, 60 s).
download_bill(bill_url, state, county, parcel_id, tax_year)Used on the web-research route. Needs a link, parcel and year. A PDF response is saved as is; an HTML page is rendered. Any exception becomes available: False with the reason.

Confidence and cost: confidence.py, cost.py

confidence.score(address_check, parcel, agency) returns {score, level, summary, points_earned, points_possible, factors[]}; the rubric and weights are in the module docstring, one small function per factor. To change a weight, edit that function. agent.ask appends each call's billed usage to agent.USAGE; run.process takes cost.mark() positions between the stages and cost.between(start, end) prices each slice, then cost.combine totals them into result["cost"]. Prices come from .env (COST_INPUT_PER_MTOK, COST_OUTPUT_PER_MTOK, COST_WEB_SEARCH_EACH). A web research call made in stage 2 and reused by stage 3 is charged to stage 2. Why web research is expensive is explained in the Feature Specification, section 4a.

Trajectory and audit: trace.py, audit_file.py

run.process calls trace.start(), then trace.stage(name) before each stage. Code that calls a public service records it with trace.add(source, action, request, outcome, url); portal.py records each Claude call with trace.claude(action, request, outcome), which reads the last entry of agent.USAGE (filled by agent.ask from the response blocks: searches, results, pages, notes). trace.report() becomes result["audit"]. To trace a new source, call trace.add right after the call. audit_file.build(results) returns the workbook bytes; Django serves it at /jobs/<id>/audit.xlsx. The confidence rules live only in confidence.RULES, which feeds the score, the Search tab table and the audit Method sheet.

Ranking: jurisdictions.py, rank_states.py

Unchanged and independent of the search. rank_states.rank_states() gates on is_single_collector, then sorts by (confidence != "high", counties needed for 80% of housing units, total counties). jurisdictions.state_for_fips and tier_1_states are no longer called by anything.

6. Module reference: Django UI

Run from the project folder: python django_ui/manage.py migrate once, then python django_ui/manage.py runserver, and open http://127.0.0.1:8000/.

FileRole
config/settings.pySets ROOT (project folder), changes the working directory to it and adds it to sys.path, so the views can import single_collector. SQLite database at django_ui/db.sqlite3. DEBUG on and only localhost allowed unless environment variables say otherwise. SEARCH_TIMEOUT_SECONDS (30 minutes) and DOWNLOADS_DIR.
search/models.pySearchJob: the queries, status, results and error of one search or batch. title summarises the first query.
search/jobs.pystart(queries) creates the job and a daemon worker thread. run(job_id) writes the queries to a temp CSV and runs python -m single_collector.run --file ... --manifest ... in a separate process, then stores the manifest as the job's results. refresh(job) marks a "running" job as failed if its worker is gone (the server restarted).
search/forms.pySearchForm: mode (address, parcel ID, both) decides which fields are required; the state must be two letters. query() returns the pipeline's query dict with unused fields empty. BatchForm: lines or a CSV upload, at most 200 searches.
search/views.pyindex (start a search), job and job_status (page and JSON for polling), use_parcel (re-search by a suggested parcel), history, quick (stages 1 and 2 in-process), batch, rank (live Census, on demand), jurisdictions_page, download (serves only PDFs under downloads/).
search/templatetags/search_extras.pyFilters: status_help, status_tone, pdf_url, pretty, spaced. STATUS_HELP is the text for each status.
templates/search/base.html (layout and styles, dark mode), page templates, and shared partials: _search_form.html (with a little JavaScript that shows only the fields the chosen search type uses), _check.html, _parcel.html (with the suggested-parcels table and its "Search with this parcel" buttons), _agency.html, _result.html.

9. Error handling and the status model

There are few try/except blocks, only where a failure must not stop the work:

WhereCatchesResult
stages.find_validate_agencyAny exception in an adapter's statement captureFlag "County portal script failed"; falls back to web research
bill.download_billAny exception fetching or rendering a bill linktax_bill = {available: false, reason}
CLI loop in run.pyAny exception for one searchA record with status error; the rest continue
jobs.run (Django)Any exception in a worker threadThe job becomes failed with the error; a thread must always leave the job in a final state
views.quick, views.rankNetwork or service problemsAn error message on the page instead of a server error

Expected outcomes that are not exceptions: no Census match, no parcel, several parcels, no agency. They are statuses with a reason.

How the final status is chosen (run.process)

no address and no parcel id                                  -> error
address invalid and no parcel id                             -> invalid_address
parcel status is not "matched"                               -> parcel_not_found | parcel_ambiguous | county_needed | county_unknown | invalid_address
agency status is not "found"                                 -> agency_not_found
agency has separate collectors                               -> exception_multi_agency
parcel verified AND agency validated                         -> success
otherwise (found by web research, not confirmed)             -> found_unverified
(any exception in process, caught by the CLI loop)          -> error

success means verified. The parcel is in the county's own records and the agency was read from the county's statement, with the parcel number confirmed on it. Web-research results are found_unverified even when they look right. A success result can still have no bill if the PDF could not be saved, so check tax_bill.available separately.

10. Design decisions and the incidents behind them

DecisionWhy (what happened)
Three named stages, each validating and explainingA search for 4800 Ravenna Ave NE returned the county but a blank parcel. The Census accepted the address by interpolation; King County has no such parcel. The old code gave no reason and never showed the parcel's address.
Suggest nearby parcels; never pick oneA bill for the wrong property is worse than none. The user chooses, or enters a parcel ID.
Parcel found by address text in the county GIS, not by coordinatesCensus points are interpolated and usually fall outside the parcel polygon.
No fixed lists: county from the Census, agency from the statementThe request was a dynamic search. The earlier design skipped "fragmented" states with a config file and typed each county's agency into its script. Now the county code comes from the Census, the agency name, address and taxing bodies from the live statement page, and an unknown county is researched on the web.
Adapters remain, but hold no agency dataDeterministic parcel search and statement access need each county's GIS service and page steps. Everything else is read at run time. Claude cannot fill portal forms, so web research alone gave third-party parcel ids and no bills.
validated requires the parcel number on the statement pageGives a concrete, checkable link between the parcel and the agency answer.
found_unverified statusA New Jersey test reported success for a parcel from a third-party source with an unvalidated agency. A plain success should mean verified.
Claude's answers always carry every key (first_json_object)Replies were wrapped in code fences, followed by commentary, or plain prose. A strict parse crashed a whole run once. Missing keys now default instead of raising KeyError.
Per-search error isolation and NOT_GEOCODEDOne crash lost every earlier result; a malformed address stopped a batch of 10 or more; addresses the batch geocoder could not match were geocoded again one by one.
Do not bypass CloudflareSan Francisco and Orange County FL sit behind a bot challenge. They are a reported limit, not something to defeat.
Django runs the pipeline in a subprocess from a worker threadSearches take minutes and drive a headless browser, which does not belong inside a web request or the server's event loop (the Streamlit version hit the same Windows problem). A job table plus polling keeps the page responsive and keeps history.
The CLI takes --manifestConcurrent jobs must not overwrite the shared output/manifest.json; each job gets its own file.
Ranking uses visible signals, not a weighted scoreAny weights would be arbitrary and would hide why a state ranks where it does.

12. Extension recipes

A. Add a county adapter

  1. Open the county's tax portal by hand. Check it loads without a CAPTCHA or "verifying you are human" page. If it does not, the county stays on the web-research route.
  2. Find how to turn an address and a parcel id into parcel rows without the browser: usually a public ArcGIS .../MapServer/N/query on the assessor's site. Check the address field's format (case, padding, abbreviations) and which field holds the parcel id.
  3. Walk from a parcel id to the statement by hand and note the selectors and the final element that proves the statement is showing.
  4. Create portals/<county>_<st>.py. Do not put any agency name or address in it:
import re
import requests

COUNTY_CODE = "32003"                       # state FIPS + county FIPS (Clark County, NV)
PARCELS = "https://.../MapServer/0/query"


def parcel_rows(where):
    """Return rows shaped {"parcel_id", "parcel_address", "city", "zip"}."""
    ...


def search_by_parcel(parcel_id):
    return parcel_rows(f"APN='{re.sub(r'[^0-9A-Za-z-]', '', parcel_id)}'")


def rows_on_street(core_word, zip_code):
    word = re.sub(r"[^A-Z0-9]", "", core_word.upper())
    return parcel_rows(f"UPPER(ADDRESS) LIKE '%{word}%' AND ZIP='{re.sub(r'[^0-9]', '', zip_code)}'")


def open_statement(page, parcel_id):
    page.goto(f"https://.../{parcel_id}", wait_until="domcontentloaded")
    page.get_by_text("Tax Statement").wait_for(timeout=20000)   # a real wait, not a sleep
    return "2026"                                                # the tax year shown
  1. Register it in portals/__init__.py (import it and add it to the tuple that builds PORTALS).
  2. Test alone: python -m single_collector.portals 32003 --parcel <id>, and the street search with --street "..." --zip .... Open the PDF and compare amounts and parcel with the portal.
  3. Test through the pipeline by address, by parcel id, with a nonexistent number (expect suggestions), and with a multi-parcel address (expect parcel_ambiguous). Check the agency read from the page makes sense and validated is true.

B. Add a status or a field to the record

  1. Return it from run.process (and, for a new parcel problem, add it to PARCEL_PROBLEMS).
  2. Add the text to STATUS_HELP and, if useful, show the field in the partial templates.
  3. Update the status table in the docs.

C. Add a page to the Django UI

  1. Write the view in views.py. For anything that takes more than a couple of seconds or drives a browser, create a job with jobs.start(queries) instead of working in the request.
  2. Add the route in urls.py and a template that extends search/base.html; add a link in the header there.
  3. If the template uses the custom filters or includes a partial that does, load search_extras in that file.

D. Make the multi-agency check stronger

Today separate_collectors is what Claude reports from the page or the web. A stronger check compares the statement's itemised taxing bodies with the Census city and school district: if the property is in a city or school district that does not appear on the statement, name it. Implement it in agency_from_statement, where both the page text and address_check are available.

E. Handle blocked portals

Do not add stealth or CAPTCHA-solving code. Options that stay within the sites' terms: an assessor or treasurer open-data download, a data agreement with the portal vendor, or leave the county on the web-research route (which already reports found_unverified and no bill). An adapter can raise a dedicated exception from open_statement when it meets a challenge page, so the flag says "blocked by bot protection".

F. Process many searches faster

Geocoding is already batched. The slow steps are web research (minutes) and adapter browsing (about 30 seconds). Parallelise with a small worker pool, one Chromium per worker, one request at a time per county site. Fix issues 8 and 10 first, and move the Django jobs to a proper queue.

Debugging an adapter

  • Run python -m single_collector.portals .... If the parcel is not found, call search_by_parcel or rows_on_street directly and print the rows.
  • To watch the browser, change p.chromium.launch() to p.chromium.launch(headless=False, slow_mo=300) in portals/__init__.py.
  • At the failing step call page.screenshot(path="debug.png") or print page.inner_text("body")[:2000].
  • Always compare the saved PDF with the portal: parcel number, address and amounts must match.

Debugging Claude's side

Print the raw reply in portal.first_json_object. Failures are almost always prose instead of JSON, or an answer that contradicts the page text. For read_statement, print captured["page_text"] to see exactly what Claude was given.

Debugging a Django job

A failed job stores the pipeline's error output in SearchJob.error (visible on the job page). To reproduce, run the same search with python -m single_collector.run. The job's temp files are under the system temp folder in search-*.

14. Glossary

TermMeaning
Parcel ID / APN / PINThe assessor's parcel number. The format differs by county (Maricopa 118-50-094, King 1985200495) and is unique only within a county.
FIPS / county codeFederal numeric codes: 2 digits for a state, 3 for a county. A "county code" here is both joined (Maricopa = 04013).
TIGERwebThe Census Bureau's boundary map service (counties, cities, school districts).
ArcGIS REST queryThe standard HTTP query interface of county GIS servers (.../MapServer/N/query?where=...).
AdapterA module in portals/ giving deterministic parcel search and statement access for one county.
Web research routeThe path for a county without an adapter: Claude with web search and fetch returns a JSON answer. Results are unverified.
Verified / validatedVerified: the parcel is in the county's own records. Validated: the agency was read from the county's statement and the parcel number is on it.
Collector modelsingle (several taxing bodies on one statement), multiple (a separate collector is named), unknown (the source does not say).
ManifestThe JSON list of result records from one CLI run (--manifest).
Cloudflare TurnstileA bot challenge some portals (the county-taxes family) show before loading.
